# Roots v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an executable, deterministic Roots v0.1 CLI/library that reconstructs provenance from authorized local Markdown/text and JSON/JSONL records, interprets evidence oldest-to-newest, follows back-references, distinguishes literal origin from conceptual ancestry, and emits verifiable provenance receipts.

**Architecture:** A dependency-light Python package separates source discovery/normalization from chronological interpretation. Source adapters emit normalized `EvidenceEvent` records; the chronology engine creates an explicit oldest-first partial order; the lineage engine classifies literal/semantic roles and requests back-reference expansion; the verifier enforces provenance invariants; the receipt renderer emits machine-readable JSON and concise Markdown. Semantic/model-assisted expansion remains an extension interface in v0.1, never the authority for chronology or origin.

**Tech Stack:** Python 3.12+, standard library runtime (`dataclasses`, `datetime`, `hashlib`, `json`, `pathlib`, `re`, `argparse`, `typing`), `pytest>=8` as the only development/test dependency.

**Spec:** `docs/superpowers/specs/2026-09-16-roots-provenance-engine-design.md`

## Global Constraints

- Provenance interpretation MUST proceed from oldest to newest event time after candidate normalization.
- Discovery order, search rank, ingestion order, filesystem order, and display order MUST NOT establish lineage position.
- The oldest available record MUST be labeled `EARLIEST_ACCESSIBLE_EVIDENCE` unless stronger origin evidence is established.
- `FIRST_LITERAL_OCCURRENCE` and `CONCEPTUAL_ANCESTOR` are distinct relations.
- A newly resolved earlier back-reference MUST force chronology rebuild and oldest-first replay.
- Direct source evidence and inferred lineage hypotheses MUST have distinct epistemic status.
- Corrections and supersessions MUST preserve earlier historical records.
- Missing links MUST remain explicit gaps; the engine MUST NOT invent bridge events.
- Current meaning MUST NOT be projected backward into earlier records.
- Every receipt MUST disclose source attempts, coverage, gaps, unresolved references, conflicts, verification results, and completeness relative to accessible sources.
- v0.1 source adapters are limited to filesystem Markdown/text and JSON/JSONL records. Git/connector/database/vector adapters are deferred.
- Public fixtures MUST be synthetic and MUST NOT copy private Vera history.
- Runtime dependencies stay in the Python standard library for v0.1; only `pytest` is allowed as a development dependency.

- [ ] **Step 4: Implement replay-based lineage traversal**

Core control flow:

```python
for replay in range(max_replays + 1):
    discovery = discover(target, adapters)
    ordered_groups = order_events(discovery.events)
    result = assess_oldest_first(target, ordered_groups)
    new_events = resolve_new_back_references(result, adapters)
    if not new_events:
        return result.with_replay_count(replay)
    seed_discovery_with(new_events)
raise ReplayLimitExceeded(...)
```

The implementation may use an internal accumulated-event map rather than literally rerunning adapter discovery, but the semantic requirement is unchanged: after older evidence is added, all lineage assessments are recomputed from the oldest event.

- [ ] **Step 5: Implement literal role classification conservatively**

Rules for deterministic v0.1:

1. First chronological event with literal/normalized literal match receives `FIRST_LITERAL_OCCURRENCE`.
2. Earliest chronological group receives `EARLIEST_ACCESSIBLE_EVIDENCE` whether or not literal.
3. `ORIGIN_CLAIM`, `CORRECTION`, `SUPERSESSION`, `FORMALIZATION`, and explicit derivation edges are assigned only from structured metadata fields or explicit adapter references; prose heuristics cannot promote them to direct evidence.
4. Semantic conceptual ancestry is accepted only when supplied as typed metadata (`relation=CONCEPTUAL_ANCESTOR`) in v0.1. Free-form LLM semantic classification is deferred behind a future extension interface.
5. Tied/overlapping timestamps can yield multiple earliest-accessible or first-literal candidates; do not break ties by source order.
